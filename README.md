# Домашнее задание к занятию «Уязвимости и атаки на информационные системы» — Петров Павел

### Задание 1

Я скачал и установил Metasploitable 2 — специально уязвимую Linux-виртуальную машину для практики в области информационной безопасности. Виртуальную машину запустил в изолированной сети Host-only, определил её IP-адрес командой `ip a` и просканировал с помощью Nmap.

Для сканирования использовал команду:

nmap -sS -sV -p- <IP_Metasploitable>


Параметр `-sV` позволяет определить не только открытые порты, но и версии запущенных сетевых служб.

По результатам сканирования в Metasploitable разрешены следующие сетевые службы:

- FTP — порт 21, vsftpd 2.3.4;
- SSH — порт 22;
- Telnet — порт 23;
- SMTP — порт 25;
- DNS — порт 53;
- HTTP — порт 80, Apache;
- SMB/Samba — порты 139 и 445;
- NFS — порт 2049;
- MySQL — порт 3306;
- PostgreSQL — порт 5432;
- VNC — порт 5900;
- IRC — порт 6667, UnrealIRCd;
- Apache Tomcat — порт 8180.

В ходе анализа были обнаружены следующие уязвимости:

1. **vsftpd 2.3.4 — backdoor command execution**  
   Уязвимость связана с FTP-сервером на порту 21. В версии vsftpd 2.3.4 присутствовал бэкдор, который позволял получить удалённый доступ к системе и выполнять команды.  
  
2. **UnrealIRCd 3.2.8.1 — backdoor command execution**  
   На порту 6667 работает IRC-сервер UnrealIRCd. В уязвимой версии возможно выполнение произвольных команд на сервере через специально сформированный запрос.  

3. **Samba 3.0.20 — username map script command execution**  
   На портах 139 и 445 работает служба Samba. Уязвимость позволяет выполнить произвольные команды на целевой системе через неправильно настроенный параметр .  
  
Таким образом, Metasploitable содержит большое количество устаревших и небезопасных сетевых служб. Для защиты подобной системы необходимо закрывать неиспользуемые порты, обновлять программное обеспечение, отключать устаревшие протоколы, такие как Telnet, а также ограничивать доступ к сервисам с помощью межсетевого экрана.

## Задание 2. Сканирование Metasploitable в режимах SYN, FIN, Xmas и UDP

Сканирование выполнялось в изолированной лабораторной сети VirtualBox. Обе виртуальные машины были подключены к адаптеру VirtualBox Host-Only Ethernet Adapter.

Параметры лаборатории:

сканирующая машина Kali Linux — 192.168.56.102;

целевая машина Metasploitable — 192.168.56.101;

сетевой интерфейс Kali Linux — eth0;

инструмент сканирования — Nmap;

инструмент захвата и анализа трафика — Wireshark.

Перед началом работы доступность Metasploitable была проверена командой:

ping -c 3 192.168.56.101
Все три пакета были доставлены без потерь.

Команды для сканирования
SYN-сканирование:

sudo nmap -sS -n -Pn --reason 192.168.56.101
FIN-сканирование:

sudo nmap -sF -n -Pn --reason 192.168.56.101
Xmas-сканирование:

sudo nmap -sX -n -Pn --reason 192.168.56.101
UDP-сканирование 20 наиболее распространённых UDP-портов:

sudo nmap -sU -n -Pn --reason --top-ports 20 192.168.56.101
Отличия режимов и ответы сервера
Режим	Что отправляет Nmap	Ответ открытого порта	Ответ закрытого порта
SYN (-sS)	TCP-пакет с флагом SYN	SYN, ACK	RST, обычно RST, ACK
FIN (-sF)	TCP-пакет с флагом FIN	Обычно ответа нет	RST; в данном захвате — RST, ACK
Xmas (-sX)	TCP-пакет с флагами FIN, PSH и URG	Обычно ответа нет	RST; в данном захвате — RST, ACK
UDP (-sU)	UDP-датаграмму	Возможен UDP-ответ либо отсутствие ответа	Обычно ICMP «порт недоступен»: тип 3, код 3
1. SYN-сканирование
При SYN-сканировании сканер отправляет TCP-пакет с флагом SYN. Открытый порт отвечает SYN, ACK, после чего сканирующая машина отправляет RST. Полное TCP-соединение не устанавливается.

Закрытый порт отвечает пакетом с флагом RST. Если ответ отсутствует после повторных попыток или приходит определённая ICMP-ошибка, Nmap определяет порт как filtered.

В выполненном захвате для TCP-порта 21 зафиксирована последовательность:

192.168.56.102 → 192.168.56.101: SYN
192.168.56.101 → 192.168.56.102: SYN, ACK
192.168.56.102 → 192.168.56.101: RST
Ответ SYN, ACK подтверждает, что на момент сканирования TCP-порт 21 был открыт. На скриншоте показаны все три пакета, а в нижней панели раскрыты флаги ответа сервера: Flags: 0x012 (SYN, ACK).

Для отображения обмена использовался фильтр:

ip.addr == 192.168.56.101 && tcp.port == 21

2. FIN-сканирование
При FIN-сканировании сканер отправляет TCP-пакет с флагом FIN без предварительного установления соединения.

Закрытый порт отвечает пакетом с флагом RST, а открытый обычно не отвечает. При отсутствии ответа Nmap показывает состояние open|filtered: порт может быть открыт либо пакеты могут блокироваться межсетевым экраном.

В выполненном захвате Kali отправляет FIN-пакет на TCP-порт 554 Metasploitable. Сервер возвращает RST, ACK. В деталях исходящего пакета отображается Flags: 0x001 (FIN). Наблюдаемый ответ соответствует закрытому TCP-порту 554.

Для отображения нужного обмена использовался фильтр:

ip.addr == 192.168.56.101 && tcp.port == 554 && frame.number >= 2031
Ограничение по номеру кадра исключает из отображения более ранние пакеты этого файла захвата.

3. Xmas-сканирование
При Xmas-сканировании сканер отправляет TCP-пакет с одновременно установленными флагами FIN, PSH и URG.

Закрытый порт отвечает пакетом с флагом RST, а открытый обычно игнорирует такую пробу. При отсутствии ответа Nmap показывает состояние open|filtered.

Отличие от FIN-сканирования заключается в наборе флагов исходящего пакета: FIN, PSH и URG вместо одного FIN. Поведение при FIN- и Xmas-сканировании зависит от реализации TCP/IP-стека целевой системы.

В выполненном захвате на TCP-порт 554 Metasploitable отправляется пакет с флагами FIN, PSH и URG. В его деталях отображается Flags: 0x029 (FIN, PSH, URG). Сервер отвечает RST, ACK, что соответствует закрытому TCP-порту 554.

Для отображения обмена использовался фильтр:

ip.addr == 192.168.56.101 && tcp.port == 554

4. UDP-сканирование
При UDP-сканировании сканер отправляет UDP-датаграммы. UDP не использует процедуру установления соединения и TCP-флаги.

Если служба возвращает UDP-ответ, Nmap определяет порт как open. Если приходит ICMP-сообщение «порт недоступен» — тип 3, код 3, — порт определяется как closed.

Если ответа нет, Nmap показывает состояние open|filtered, поскольку открытая служба может игнорировать неподходящий запрос, а межсетевой экран может отбрасывать пакеты. Некоторые другие ICMP-ошибки приводят к состоянию filtered.

В данной работе UDP-сканирование было ограничено 20 наиболее распространёнными UDP-портами.

ICMP-ответ на UDP-пробу
В пакете №20 Metasploitable 192.168.56.101 отправляет Kali 192.168.56.102 ICMP-сообщение со следующими значениями:

Type: 3 — Destination unreachable
Code: 3 — Port unreachable
Внутри ICMP-сообщения приведены заголовки исходного IP-пакета и UDP-датаграммы с портом назначения 514. Таким образом, полученный ответ относится к отправленной UDP-пробе и подтверждает закрытое состояние UDP-порта 514 на момент проверки. Этот вывод не распространяется автоматически на остальные проверенные UDP-порты.

Для поиска таких сообщений использовался фильтр:

ip.src == 192.168.56.101 && icmp.type == 3 && icmp.code == 3

Вывод
В ходе работы выполнено сканирование Metasploitable в режимах SYN, FIN, Xmas и UDP. Сетевой трафик записан и проанализирован в Wireshark.

При SYN-сканировании TCP-порта 21 наблюдалась последовательность SYN → SYN, ACK → RST, соответствующая открытому порту. При FIN- и Xmas-сканировании TCP-порта 554 сервер возвращал RST, ACK, что соответствует закрытому порту. При UDP-сканировании на пробу порта 514 получен ICMP-ответ «порт недоступен» — тип 3, код 3, подтверждающий закрытое состояние этого UDP-порта.

Режимы SYN, FIN и Xmas используют TCP и различаются флагами отправляемых пакетов. UDP-сканирование использует UDP-датаграммы, а состояние портов определяется по UDP-ответам, сообщениям ICMP либо отсутствию ответа.

Отсутствие ответа не всегда означает, что порт открыт: причиной также может быть фильтрация трафика. Поэтому при интерпретации результатов необходимо учитывать режим сканирования и характер полученных ответов.
