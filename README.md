# Домашнее задание к занятию «Уязвимости и атаки на информационные системы» — Петров Павел

### Задание 1

Я скачал и установил Metasploitable 2 — специально уязвимую Linux-виртуальную машину для практики в области информационной безопасности. Виртуальную машину запустил в изолированной сети Host-only, определил её IP-адрес командой `ip a` и просканировал с помощью Nmap.

Для сканирования использовал команду:

nmap -sS -sV -p- <IP_Metasploitable>


Параметр `-sV` позволяет определить не только открытые порты, но и версии запущенных сетевых служб.

По результатам сканирования в Metasploitable разрешены следующие сетевые службы:

- FTP — порт 21, vsftpd 2.3.4;
- SSH — порт 22;
- Telnet — порт 23;
- SMTP — порт 25;
- DNS — порт 53;
- HTTP — порт 80, Apache;
- SMB/Samba — порты 139 и 445;
- NFS — порт 2049;
- MySQL — порт 3306;
- PostgreSQL — порт 5432;
- VNC — порт 5900;
- IRC — порт 6667, UnrealIRCd;
- Apache Tomcat — порт 8180.

В ходе анализа были обнаружены следующие уязвимости:

1. **vsftpd 2.3.4 — backdoor command execution**  
   Уязвимость связана с FTP-сервером на порту 21. В версии vsftpd 2.3.4 присутствовал бэкдор, который позволял получить удалённый доступ к системе и выполнять команды.  
  
2. **UnrealIRCd 3.2.8.1 — backdoor command execution**  
   На порту 6667 работает IRC-сервер UnrealIRCd. В уязвимой версии возможно выполнение произвольных команд на сервере через специально сформированный запрос.  

3. **Samba 3.0.20 — username map script command execution**  
   На портах 139 и 445 работает служба Samba. Уязвимость позволяет выполнить произвольные команды на целевой системе через неправильно настроенный параметр .  
  
Таким образом, Metasploitable содержит большое количество устаревших и небезопасных сетевых служб. Для защиты подобной системы необходимо закрывать неиспользуемые порты, обновлять программное обеспечение, отключать устаревшие протоколы, такие как Telnet, а также ограничивать доступ к сервисам с помощью межсетевого экрана.

## Задание 2. Сканирование Metasploitable в режимах SYN, FIN, Xmas и UDP

### Команды для сканирования

Используется IP-адрес Metasploitable: `192.168.56.101`.

SYN-сканирование:


sudo nmap -sS -n -Pn --reason 192.168.56.101


FIN-сканирование:


sudo nmap -sF -n -Pn --reason 192.168.56.101


Xmas-сканирование:


sudo nmap -sX -n -Pn --reason 192.168.56.101


UDP-сканирование 20 наиболее распространённых UDP-портов:


sudo nmap -sU -n -Pn --reason --top-ports 20 192.168.56.101


### Отличия режимов и ответы сервера

| Режим | Что отправляет Nmap | Ответ открытого порта | Ответ закрытого порта |
|---|---|---|---|
| SYN (`-sS`) | TCP-пакет с флагом SYN | SYN, ACK | RST, обычно RST, ACK |
| FIN (`-sF`) | TCP-пакет с флагом FIN | Обычно ответа нет | RST |
| Xmas (`-sX`) | TCP-пакет с флагами FIN, PSH и URG | Обычно ответа нет | RST |
| UDP (`-sU`) | UDP-датаграмму | Возможен UDP-ответ либо отсутствие ответа | Обычно ICMP «порт недоступен»: тип 3, код 3 |

### SYN-сканирование

Сканер отправляет TCP-пакет с флагом SYN. Открытый порт отвечает SYN, ACK, после чего сканирующая машина отправляет RST. Полное TCP-соединение не устанавливается.

Закрытый порт отвечает RST. Если ответ отсутствует после повторных попыток или приходит определённая ICMP-ошибка, Nmap определяет порт как filtered.

В Wireshark для открытого порта ожидается последовательность:

SYN → SYN, ACK → RST.

### FIN-сканирование

Сканер отправляет TCP-пакет с флагом FIN без предварительного установления соединения.

Закрытый порт отвечает RST, а открытый обычно не отвечает. При отсутствии ответа Nmap показывает open|filtered: порт может быть открыт, либо пакеты могут блокироваться межсетевым экраном.

### Xmas-сканирование

Сканер отправляет TCP-пакет с флагами FIN, PSH и URG.

Закрытый порт отвечает RST, а открытый обычно игнорирует пакет. При отсутствии ответа Nmap показывает open|filtered.

В Wireshark отличие от FIN-сканирования заключается в наборе флагов исходящего пакета: FIN, PSH и URG вместо одного FIN.

Поведение при FIN- и Xmas-сканировании зависит от реализации TCP/IP-стека целевой системы.

### UDP-сканирование

Сканер отправляет UDP-датаграммы. UDP не использует процедуру установления соединения и TCP-флаги.

Если служба возвращает UDP-ответ, Nmap определяет порт как open. Если приходит ICMP-сообщение «порт недоступен» — тип 3, код 3, — порт определяется как closed.

Если ответа нет, Nmap показывает open|filtered, поскольку открытая служба может игнорировать неподходящий запрос, а межсетевой экран может отбрасывать пакеты. Некоторые другие ICMP-ошибки приводят к состоянию filtered.

### Вывод

SYN, FIN и Xmas используют TCP и отличаются флагами отправляемых пакетов. UDP-сканирование использует UDP-датаграммы.

При SYN-сканировании открытый порт отвечает SYN, ACK, а закрытый — RST. При FIN и Xmas закрытый порт отвечает RST, а открытый обычно не отвечает. При UDP-сканировании закрытый порт обычно возвращает ICMP-сообщение о недоступности порта, а открытый может отправить UDP-ответ или не ответить.

Отсутствие ответа не всегда означает, что порт открыт: причиной также может быть фильтрация трафика.
